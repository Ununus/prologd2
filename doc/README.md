# Документация PrologD

В этом каталоге лежат пять документов на языке Typst:

| Файл | Назначение |
|------|------------|
| `help.typ` | руководство пользователя: синтаксис, типы данных, все встроенные предикаты, примеры, командная строка |
| `gui.typ` | графический интерфейс: запуск, вкладки и файлы, редактор, автодополнение, горячие клавиши, настройки |
| `lessons.typ` | курс уроков: как устроен урок, порядок тем, как уроки проверяются, что было раньше |
| `technical.typ` | техническое описание: модель термов, унификация, машина вывода, длинная арифметика, разбор, модули, тестирование |
| `prologd-diff.typ` | изменения синтаксиса и поведения относительно первоначального Пролога-Д, с примерами «было/стало» |

Документы написаны на русском языке; комментарии и идентификаторы в примерах кода
приводятся без изменений.

Плюс два значка, которые документы ставят на первую страницу, — `prologd2.png`
(эмблема проекта) и `csu.png` (эмблема вуза): их рисует `style.typ` по вызову
`#logos()`, и лежат они здесь, а не в `src/gui/assets`, чтобы папка `doc` собиралась
сама по себе (подробнее — раздел «Эмблемы первой страницы» ниже).

Плюс `builtins.json` — не документ, а данные: одна запись на встроенный предикат
(краткое описание, варианты вызова, раздел руководства, английское имя).  Из него
`help.typ` строит таблицу английских имён (приложение 17), а графическая оболочка
показывает описание в подсказке и по `F1`; согласованность с интерпретатором и с
руководством проверяет `src/gui/tests/test_reference.py`.  Цель `docs` его не
собирает и PDF для него не делает — как и для `style.typ`.

## Оформление листингов

Листинги во всех документах рисует общий файл `style.typ`: он превращает блок кода
в панель с фоном, скруглёнными углами и цветной полосой слева. Полоса показывает,
что это за листинг:

| Полоса | Листинг | Язык в тройных кавычках |
|--------|---------|--------------------------|
| синяя | программа на Пролог-Д | `prolog` |
| фиолетовая | фрагмент на C++ | `cpp` |
| зелёная | команды оболочки: их набирают, а не читают | `sh` |
| серая | текст без подсветки: структура каталогов, вывод | язык не указан |

Документ подключает стиль первыми строками:

```typst
#import "style.typ": apply
#show: apply
```

Именно `#show: apply`, а не `#include`: правила оформления действуют на то, что
идёт дальше по документу, и внутри включаемого файла они бы ни на что не повлияли.
`style.typ` — не документ, а общий файл; цель `docs` его не собирает и PDF для него
не делает.

Панель шире полосы текста на пару миллиметров: строке кода достаётся немного
больше места, чем строке обычного текста. Кегль кода не переопределяется — у Typst
для листингов свой, меньше основного текста, --- и длинная строка переносится так
же, как переносилась до панелей.

## Эмблемы первой страницы

Тот же `style.typ` рисует эмблемы: `#logos()` ставит `prologd2.png` и `csu.png`
рядом, в левом верхнем углу первой страницы (высота у обеих одна — 1 см, зазор
4 мм). Вызов стоит в каждом документе сразу после настройки страницы, до отступа
перед заголовком:

```typst
#logos()
```

Значки не мешают вёрстке: `place` не занимает места в потоке, поэтому центрированный
заголовок остаётся там, где был. Эмблемы попадают и в поставку — рядом с PDF и
исходниками `*.typ` (иначе поставленные исходники не собрать).

## Сборка PDF

Для сборки нужен компилятор [Typst](https://typst.app/) (`typst`). Если он
установлен, достаточно выполнить из корня проекта:

```sh
cmake --build build --target docs
```

PDF-файлы кладутся рядом с исходниками, в этот же каталог `doc/`. Они — артефакт,
а не исходный текст, поэтому перечислены в `.gitignore`; правьте `.typ`, а PDF
пересобирайте. Можно собрать и вручную:

```sh
typst compile doc/help.typ       doc/help.pdf
typst compile doc/gui.typ        doc/gui.pdf
typst compile doc/lessons.typ    doc/lessons.pdf
typst compile doc/technical.typ  doc/technical.pdf
typst compile doc/prologd-diff.typ doc/prologd-diff.pdf
```

Отдельную страницу можно посмотреть, не открывая PDF:

```sh
typst compile --format png --ppi 105 --pages 2-3 doc/gui.typ "$env:TEMP/g{p}.png"
```

Если `typst` не установлен, его можно поставить как Python-пакет (компилятор
входит в пакет):

```sh
python3 -m venv .venv && .venv/bin/pip install typst
.venv/bin/python -c "import typst; typst.compile('doc/help.typ', output='doc/help.pdf')"
```

Если `typst` недоступен, цель `docs` просто выводит сообщение и завершается
успешно: сборка интерпретатора от документации не зависит.

## Как поддерживать документацию в актуальном состоянии

* Новый встроенный предикат добавляется в `help.typ` в том же изменении, что и
  его реализация.
* Любое изменение синтаксиса или наблюдаемого поведения языка фиксируется в
  `prologd-diff.typ` с примером «было/стало».
* Внутренние решения (структуры данных, алгоритмы, компромиссы) описываются в
  `technical.typ`; краткие решения---в `ai/decisions.md`.
* У нового листинга указывается язык (`prolog`, `cpp`, `sh`), иначе панель
  получится серой: цвет полосы берётся из `style.typ`.
