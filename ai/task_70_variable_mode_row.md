# task_70 — Строка «Имена переменных»: три пункта вместо четырёх

**Status:** done (2026-10-06)
**Depends on:** task_67 (режимы имён), task_69 (прошлый круг мелких правок)

## Что просили

Убрать из строки «Имена переменных» значение «по первой строке файла» и оставить три
пункта: «как в ISO: переменная с большой буквы», «по-старому: одна буква —
переменная» и третий, как он и был, — «то же плюс имена с апострофом».  Файл,
объявивший `:- ИМЕНА(N).`, важнее строки настроек.

## Почему «по первой строке файла» ничего не значило

Маркер главнее настройки и в интерпретаторе (`parseSource`), и в окне
(`refresh_variable_mode`), а режим 0 не уходит на провод (`protocol._variable_mode`):
оба пункта давали один и тот же запрос и одно и то же поведение для любого файла.
Строка выбора работает только для файла **без** маркера, и там умолчание и есть ISO.
Значит, «по первой строке файла» было вторым способом сказать «как в ISO».

## Как стало

* `DEFAULT_VARIABLE_MODE = "0"`, `VARIABLE_MODES = ("0", "1", "2")`, и подписи
  пунктов — те, что назвал учитель.
* `Settings.variable_mode_number` — просто число выбранного пункта: `_choice` уже
  гарантирует один из трёх.
* Правило «маркер важнее» не тронуто ни в C++, ни в окне: строка остаётся ответом на
  вопрос «в каком диалекте написан файл, который молчит».
* Конфигурация, в которой записано старое `auto`, читается как `0` (`_choice` при
  несовпадении возвращает умолчание), поэтому поведение для непомеченного файла у
  тех, кто окно уже запускал, не изменилось.
* `doc/gui.typ` — абзац про режим чтения имён переписан; в `test_window.py` рядом с
  проверкой маркера появилась строка, что умолчание строки — ISO.
