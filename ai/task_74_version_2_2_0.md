# task_74 — Версия 2.2.0 и новый портативный пакет

**Status:** done (2026-10-08)

## Что просили

Поднять версию до 2.2.0 и собрать портативный пакет.

## Что подняли

Источник номера один — `project(prologd VERSION x.y.z)` в `CMakeLists.txt`: CMake
вкладывает его в сгенерированный `version.cpp`, откуда номер берут `--version`,
событие `ready` и встроенный `ВЕРСИЯ/0`.  Живых копий номера было четыре:

* `examples/lessons/appendix_debug.pld` — пример строки `ВЕРСИЯ` в уроке;
* `src/gui/README.md` — пример события `ready` (там же и номер протокола);
* `tools/check_dependencies.py` — путь пакета по умолчанию;
* `src/tests/CMakeLists.txt` — тест `cli_version`.

Последний и оказался ловушкой: номер стоял там литералом **с экранированными
точками** — `PASS_REGULAR_EXPRESSION "2\\.1\\.0"`.  Поиск по `2.1.0` такого не
находит (экранирование сидит между цифрами), и тест упал ровно на нём.  Литерала
больше нет: образец собирается из того же единственного источника —
`string(REPLACE "." "\\." PROLOGD_VERSION_PATTERN "${PROJECT_VERSION}")`.

Ещё поправлено `ai/conventions.md`: «протокол 13» — это 2.2.0, а не 2.1.0
(размер экрана вошёл именно в неё).

## Пакет

`tools\build_portable.ps1` — Release → ctest → документы → PyInstaller → раскладка →
проверки → zip:

* `dist\prologd-2.2.0-win64` — **303 файла**, `prologd.exe --version` внутри → `2.2.0`;
* `dist\prologd-2.2.0-win64.zip` — **37,9 МиБ** (39 786 345 байт; у 2.1.0 было
  39 753 766).

Пакеты 2.0.0 и 2.1.0 остаются рядом: выпуски друг другу не мешают.
