## Что вышло (2026-10-13, часть 107)

Номер **2.3.0**, имя продукта — `set(PROLOGD_PRODUCT_NAME "Пролог-У")` в
`CMakeLists.txt` рядом с `project(... VERSION ...)`.  Обе печатающие стороны
получили одну функцию — `versionBanner()` в генерируемом `src/prlib/src/version.cpp`:
её и печатает внутри себя `builtins.cpp` (`ВЕРСИЯ/0`), её же отдаёт флаг `--version`.  В
ответе — та же строка:

```
Пролог-У 2.3.0 (2026-10-13)
```

**Почему имя не отдано макросом.**  `PROLOGD_VERSION` живёт как `-D`, и для номера это
правильно.  Но не-ASCII значение `-D` проходит через файл ответов компилятора, а MSVC
читает его в ANSI-кодировке машины — «Пролог-У» приехало бы мохнатым.  Имя уходит в тот
же сгенерированный файл, который `configure_file` пишет UTF-8-байтами, а `prlib`
собирается с `/utf-8`.

**Следствия для скриптов и проверок.**  `--version` стало предложением:
`tools/build_portable.ps1` берёт из него первое `\d+\.\d+\.\d+` (для имени папки и для
сверки двигателя внутри пакета — дата сборки у пакета своя, сравнивать строку целиком
нельзя).  В `ai/conventions.md` в разделе Versioning появился абзац про имя продукта,
а в списке живых копий номера исправлен пункт про `cli_version` (литерала там нет со
времени task_74).  `test_window.py` больше не ждёт начала `"PrologD "` от `?ВЕРСИЯ.`:
он сверяет номер внутри баннера с номером из `ready`.

**Заодно.**  Описание движка в `--help` (было «PrologD logic programming language
interpreter»), строка в `appendix_debug.pld`, `help.typ` §13, `prologd-diff.typ` и
запись `ВЕРСИЯ` в `doc/builtins.json`.  Два литерала номера сдвинуты:
`src/gui/README.md` (пример `ready`) и `tools/check_dependencies.py` (путь пакета).

**Что не тронуто.**  Имя оболочки: заголовок окна, `ORGANIZATION`, путь настроек и
статусная строка — задачи 79 и 81.
