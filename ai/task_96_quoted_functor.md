# task_96 — Имя в кавычках как функтор: `'Вася'(…)`

**Status:** done (2026-10-22) — часть 154 в `ai/status.md`
**Depends on:** task_67/task_77 (режимы имён), task_90 (стандартный порядок)

## Откуда

Пользователь написал файл старого диалекта

```
:-ИМЕНА(1).
Вася(15, Задунайский).
```

и ISO-файл, который звал его

```
:-import("test1.pld").
?'Вася'(Лет, Фамилия).
```

и получил две разные ошибки: `test1.pld:2:1: Голова предложения должна быть
предикатом` и `test.pld:2:2: предложение должно заканчиваться точкой`.

## Что выяснено измерением

- **оригинальный движок** такой файл принимает: `Вася(15, задунайский). ?Вася(Л, Ф).`
  даёт `Л=15`, `Ф=задунайский`; то же с `Вася.` (арность 0).  Но `ф(Вася(1)).` он
  отвергает — «Перед "(" должен быть функтор», то есть прописное имя работает
  предикатом только в начале предложения.  `"Вася"(1).` он принимает;
- **наш режим 1** читает `Вася` как строковую константу (так и записано в
  `prologd-diff.typ` §3–5: `:‑ИМЕНА(1)` — это «прописное имя без кавычек —
  строковая константа»), поэтому голова из неё не получается.  Это не регресс, а
  давнее решение;
- **в ISO-режиме** `?'Вася'(…)` не разбирался вовсе: `QuotedAtom` возвращался
  атомом, а `(…)` оставалось «лишним».  При этом `?'Вася'.` разбирался и отвечал
  «не найдено: Вася/0» — то есть кавычки работали для терма, но не для функтора.

## Что сделано

- `parser.cpp`: `QuotedAtom`, за которым сразу идёт `(`, становится составным
  термом с этим именем — ISO-шный `'Вася'(X)`.  Разбор аргументов вынесен в общий
  `parseArguments(name)`, им же пользуется `parseCompoundOrAtom`;
- **строковая** константа функтором не стала: в ISO строка — список кодов, а список
  функтором быть не может, и `"Вася"(1)` по-прежнему ошибка.  Правило «прописное имя
  — предикат» из старого диалекта тоже не копируется: у нас для этого есть кавычки;
- `test_parser.cpp` — голова и цель в кавычках, атом в кавычках как терм, строка
  функтором отвергается; `test_engine.cpp` — `'Вася'(15, задунайский).` и
  `?'Вася'(Л, Ф).` дают `Лет=15`, `Фамилия=задунайский`, а `?'вася'(…)` — `НЕТ`;
- `doc/help.typ` §2 — как записывается имя предиката с заглавной буквы;
  `doc/prologd-diff.typ` §5 — прописное имя можно оставить, заключив в кавычки.

## Что осталось

- Печать ответа (`term_print.cpp`) пишет имя без кавычек: `?Х = 'Вася'.` даёт
  `Х=Вася`, а не `Х='Вася'`.  Так было и до этой задачи (строка и атом в диалекте
  печатаются одинаково — `"GNU"` тоже выходит без кавычек), и менять это надо
  отдельно, вместе с решением о печати строк;
- форматтер кавычки сохраняет (проверено на `'Вася'(15, задунайский).`), поэтому
  `test_formatter.cpp` таким файлам не мешает.
