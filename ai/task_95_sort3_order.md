# task_95 — `СОРТИРОВКА/3`: сортировка со знаком порядка

**Status:** done (2026-10-22) — часть 152 в `ai/status.md`
**Depends on:** task_90 (стандартный порядок термов)
**ADR:** `ai/decisions.md`, ADR-030

## Зачем

`СОРТИРОВКА/2` умеет ровно одно: по возрастанию и без повторов. Чего в языке не
было вовсе — **убывания**; «с повторами» закрывал `msort/2` из стандартной
библиотеки, и то только по возрастанию. `sort/4` из SWI закрывает всё, но вводит
понятие ключа (номер аргумента составного терма), которое в учебном диалекте пока
не нужно.

Поэтому — промежуточная форма: `СОРТИРОВКА(Порядок, Список, Результат)`. Она
закрывает убывание и повторы, а ключ остаётся на потом: `sort/4` ляжет сверху,
потому что `/3` определена как `sort(0, Порядок, …)`.

## Что сделано

- `builtins_lists.cpp`: общая функция `sortTerms` (устойчивая сортировка по
  стандартному порядку, снятие повторов по флагу) и два входа —
  `builtinSort` (`/2`, всегда `@<`) и `builtinSort3` (знак из первого аргумента);
- знаки: `@<` возрастание без повторов, `@=<` возрастание **с** повторами,
  `@>` убывание без повторов, `@>=` убывание **с** повторами — правило SWI для
  `sort/4`: знак, который допускает равенство, оставляет и равные;
- `add("СОРТИРОВКА", 3, builtinSort3)` — английское имя `sort/3` появляется само,
  как у любой пары;
- `badArguments` получил `index_base`: `/3` называет список «аргумент 2», а не
  «аргумент 1» (part 136); непарный хвост по-прежнему даёт короткое сообщение;
- `doc/builtins.json` (`arities: [2, 3]`), `doc/help.typ` §3.7 (подраздел с
  таблицей знаков), `doc/prologd-diff.typ`, `examples/sort.pld` (раздел про `/3`),
  `examples/README.md`;
- `test_builtins_lists.cpp` — четыре случая: знаки и повторы, совпадение с `/2`,
  отказы, счёт аргументов.
