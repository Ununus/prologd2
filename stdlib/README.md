# Стандартная библиотека

Программы на Пролог-Д, которые подключают к своей задаче. Папка лежит рядом с
`prologd.exe`: в переносной сборке — в корне пакета, в дереве исходников — в корне
репозитория.

```prolog
:- ИМПОРТ("lists.pld").
```

Интерпретатор ищет `stdlib` сам — последним, после папки подключающего файла и
каталогов ключа `-I`. Поэтому в сборке достаточно одной директивы. Каталоги `-I`
нужны только тогда, когда библиотеку берут из дерева исходников, где рядом с
интерпретатором её нет:

```sh
prologd -I stdlib -s задача.pld
```

В окне каталоги поиска перечисляют в «Правке → Настройки… → Выполнение →
Дополнительные каталоги ИМПОРТ»; сборке, где `stdlib` лежит рядом с `prologd.exe`,
настраивать ничего не надо.

## Что где

| Файл | О чём |
|---|---|
| `lists.pld` | списки: поиск, длина, края, построение, разбор, работа целью |
| `sets.pld` | множества на списках; подключает `lists.pld` |
| `sorts.pld` | приёмы сортировки; подключает `lists.pld` |
| `strings.pld` | строки: пробелы, слова, замена, разбор чисел; подключает `lists.pld` |
| `math.pld` | целые числа: делители, степени, простые |

Полный список предикатов с аргументами — в документе «Стандартная библиотека»
(`doc/library.typ`, он же PDF в сборке); короткое описание каждого предиката стоит
строкой выше него в самом файле. Как всё работает, показывает
`examples/stdlib_demo.pld`: каждая строка `%!` там — ответ интерпретатора, и тест
следит, чтобы библиотека и пример не разошлись.

## Как читать имена

Предикаты названы по-латински, как в первой библиотеке Пролог-Д, переменные —
по-русски: `member(Элемент, Список)`. Перед группой предложений одного предиката
стоит комментарий, после группы — пустая строка.

Встроенные имена заняты, и **своё предложение под таким именем не работает**:
вызов уходит встроенному предикату, а предупреждение «не найдено» появится только
там, где арности у встроенного нет вовсе. Поэтому первый элемент списка достаёт
`head/2`, а не `first/2` (`first` — английское имя встроенного `ПЕРВОЕ`).
По этой же причине в библиотеке нет `больше/2` и `меньше/2`: сравнение делают
встроенные `БОЛЬШЕ` и `МЕНЬШЕ`, и у них тот же порядок, что у `СОРТИРОВКА`.

## Что стало с первой библиотекой

| Было (`lists`) | Стало |
|---|---|
| `member/2`, `last/2`, `reverse/2`, `flatten/2`, `permutation/2`, `sublist/2`, `select/3` | те же имена |
| `size/2`, `length/2` | только `length/2` |
| `first/2` | `head/2` (имя `first` занято встроенным `ПЕРВОЕ`) |
| `next/3` | `adjacent/3` |
| `minel/2`, `maxel/2` | `min_list/2`, `max_list/2` |
| `add/3` | `append/3` |
| `delete/3`, `delall/3`, `substitute/4` | `delete/3`, `delete_all/3`, `substitute/4` — список стал первым аргументом, как у `select/3` |
| `coincide/2` | `prefix/2`; рядом появился `suffix/2` |
| `выводсписка/1` | `print_list/1` |
| `вводсписка/2` | `read_numbers/2` |
| `вводсписка/1` | `read_words/1` (в `strings.pld`) |
| `split/2` | `words/2` (в `strings.pld`) |
| `чиспис/2` | `to_numbers/2` (в `strings.pld`) |
| `больше/2`, `меньше/2` | не нужны: встроенные `БОЛЬШЕ` и `МЕНЬШЕ` |
| — (новое) | `nth/3`, `head_n/3`, `last_n/3`, `sum_list/2`, `map/3`, `filter/3`, `fold/4`, `msort/2`, `strings.pld` и `math.pld` |
| `set/2` | `set/2`, но через `СОРТИРОВКА`: без повторов по возрастанию |
| `delrepeat/2` | `unique/2`: без повторов, порядок первых вхождений сохраняется |
| `subset/2`, `equalset/2`, `unionset/3`, `intersect/3`, `difset/3` | те же имена; `intersect` и `difset` собирают ответ через `НАЙТИВСЕ` |
| `selectsort/2`, `insertsort/2`, `bubblesort/2`, `quicksort/2`, `mergesort/2`, `treesort/2` | те же имена в `sorts.pld` |
| `ins/3` | `insert/3` |
| `change/2`, `merge/3`, `halves/3` (было `splitting/3`) | те же имена |
| `maketree/2,3`, `addtree/3`, `treelist/2` | `make_tree/2,3`, `add_node/3`, `tree_list/2` |
| `heapsort/2`, `makeheap/2`, `mergeheap/3` | нет: он брал случайное число (`СЛУЧ`), чтобы выбирать поддерево, а такая сортировка не воспроизводима |
