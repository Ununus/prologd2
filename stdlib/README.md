# Стандартная библиотека

Программы на Пролог-Д, которые подключают к своей задаче. Папка лежит рядом с
`prologd.exe`: в переносной сборке — в корне пакета, в дереве исходников — в корне
репозитория.

```prolog
:- ИМПОРТ("lists.pld").
```

Интерпретатор ищет `stdlib` сам — последним, после папки подключающего файла и
каталогов ключа `-I`. Поэтому в сборке достаточно одной директивы. Каталоги `-I`
нужны только тогда, когда библиотеку берут из дерева исходников, где рядом с
интерпретатором её нет:

```sh
prologd -I stdlib -s задача.pld
```

В окне каталоги поиска перечисляют в «Правке → Настройки… → Выполнение →
Дополнительные каталоги ИМПОРТ»; сборке, где `stdlib` лежит рядом с `prologd.exe`,
настраивать ничего не надо.

## Что где

| Файл | О чём |
|---|---|
| `lists.pld` | списки: края, номер, построение, разбор, работа целью; подключает `iso.pld` |
| `sets.pld` | множества на списках; подключает `lists.pld` |
| `strings.pld` | строки: пробелы, слова, замена, разбор чисел; подключает `lists.pld` |
| `math.pld` | целые числа: делители, степени, простые; подключает `iso.pld` |
| `graphics.pld` | цвета графики: `rgb/4` и имена цветов |
| `iso.pld` | имена стандарта: списки, целые, сортировка плюс тесты типов, `once/1`, `ignore/1`, `succ/2`, `nth1/3`; никого не подключает |

Полный список предикатов с аргументами — в документе «Стандартная библиотека»
(`doc/library.typ`, он же PDF в сборке); короткое описание каждого предиката стоит
строкой выше него в самом файле. Как всё работает, показывает
`examples/stdlib.pld`: каждая строка `%!` там — ответ интерпретатора, и тест
следит, чтобы библиотека и пример не разошлись.

## Как читать имена

Предикаты названы по-латински, переменные — по-русски: `member(Элемент, Список)`.
Перед группой предложений одного предиката стоит комментарий, после — пустая строка.

Встроенные имена заняты, и своё предложение под таким именем не сработает:
вызов уйдёт встроенному предикату. Поэтому первый элемент списка достаёт
`head/2` (`first` — английское имя встроенного `ПЕРВОЕ`).
По этой же причине в библиотеке нет `больше/2` и `меньше/2`: сравнение делают
встроенные `БОЛЬШЕ` и `МЕНЬШЕ`. Порядок у них числовой: число с числом или текст с
текстом, а всё остальное — ошибка типа. Любые термы упорядочивает стандартный
порядок (`@<`, `compare/3` — раздел 5.9 руководства), им же сортирует `СОРТИРОВКА`
и `msort/2`.
